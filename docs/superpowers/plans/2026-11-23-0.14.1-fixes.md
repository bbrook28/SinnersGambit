# 0.14.1: three audit bugs — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix the three bugs the 0.14.0 audit reproduced in play: the hint that ignores the Sin, the script error when the tutorial is replayed during a roll, and the missing one-time cards for a player who skipped the lessons.

**Architecture:** All three are in `ui/dice_screen.gd`; no rule in `dice/` changes. The hint ranks the next die by what the row would pay in all (hand plus Sin) instead of the hand alone. The `?` page does not open while dice are moving. Two one-time cards reuse lesson 2's own words.

**Tech Stack:** Godot 4.7.2, GDScript. Tests: `bash tests/run_all.sh` (the checks live in `tests/ui_test.gd`).

**Spec:** `docs/audits/2026-11-23-audit-0.14.0.md` (bugs 1 to 3) and `docs/superpowers/specs/2026-11-21-tutorial-design.md` (line 68, the one-time cards).

### Task 1: The hint counts the Sin

**Files:**
- Modify: `ui/dice_screen.gd` (`next_hint`, about line 876)
- Test: `tests/ui_test.gd` (`test_demand`, `test_lessons`)

**The rule.** For each face, value = `Rules.score(cfg, row + [f]).marks + Rules.sin_marks(cfg, row + [f], s.bank)`. The hint names the face with the highest value, and only if that value is higher than the row's value now; a tie goes to the better hand. With no Sin this is today's rule.

**The words** (`<Sin>` is `sin_name()`, the change is `marks_text(delta)` as on the tag above a die):

| Case | Text |
|---|---|
| The hand gets better, the Sin's pay is unchanged | `One more 4: Pair · 1` (as today) |
| The hand gets better and the Sin's pay changes | `One more 2: Five of a kind · <pay>, Pride −1` |
| Only the Sin's pay gets better | `One more 6: Pride +4` |
| The Run branch, when the missing faces change the Sin's pay | `Needs 2: Run · 5, Pride −1` |
| No face raises the value | (empty) |

- [ ] **Step 1: Write the failing checks** in `test_demand`, under Pride, bank 0:

```gdscript
# row [6]: a second 6 loses Pride's 4, so nothing is offered
check("hint: no second 6 under Pride", h.next_hint() == "")
# row [6], the 4 picked: the pair of 4s keeps Pride's 4
check("hint: the pair that keeps the 6 alone", h.next_hint() == "One more 4: Pair · 1")
# row [3]
check("hint: Pride's 6 beats a pair", h.next_hint() == "One more 6: Pride +4")
# row [3, 4, 5, 6]
check("hint: the Run says what its 2 costs", h.next_hint() == "Needs 2: Run · 5, Pride −1")
# row [2, 2, 2, 2]
check("hint: hand and Sin together", h.next_hint() == "One more 2: Five of a kind · %d, Pride −1" % h.Rules.pay(h.cfg, 7))
```

In `test_lessons`, at lesson 3's step "Keep the 4" (row `[6]`, dice 6 and 4, nothing picked): `check("ui: lesson 3's hint does not contradict the lesson", not h.hint.text.begins_with("One more 6"))`.

- [ ] **Step 2: Run** `bash tests/run_all.sh`. Expected: the six new checks FAIL, all others pass.
- [ ] **Step 3: Change `next_hint() -> String`** to the rule and words above. The signature and the "count the picked die" behaviour stay.
- [ ] **Step 4: Run** `bash tests/run_all.sh`. Expected: PASS. Any existing hint check that runs under Pride and now reads differently is updated to the new words and listed in the commit message; checks with no Sin (lessons 1 and 2) must pass unchanged.
- [ ] **Step 5: Commit** `Hint: counts the Sin's pay, so it no longer offers a second 6 under Pride`.
